# 一次性大需求提示词模板 —— 整台工作台交给 AI

> 场景:不是加一个页面,而是**从零交付一台完整工作台**(多面板 + 数据服务 + agent 工具)。
> 单页/小改动的场景不用本模板——用生成结果页的「首次会话提示词」即可。
> 用法:先用脚手架生成项目(页面化或 `node scaffold.mjs`),再把本模板填好发给加载了项目目录的 AI。

## 模板正文(复制后替换 {{…}})

```text
这是一个刚生成的 dsh 工作台插件项目(路径 {{目标目录}},包名 {{dsh-xxx}},插件 id {{xxx}})。
本次任务是把它交付成一台完整的工作台,需求如下。请分阶段执行,每阶段验证通过再进下一阶段,禁止大爆炸式写完再测。

## 必读(动手前按序读完,不要凭记忆写代码)
1. AGENTS.md —— 项目身份、8 条红线、加页面的标准工作流
2. docs/EXAMPLES.md —— 范式索引与红线映射表(页面范式照 src/examples/ 抄,不偏离 dsh 规范)
3. 结构速览:src/client.tsx(注册)/ src/theme.ts(设计系统,只用不改)/ service/(数据层)/ index.js(路由与工具)

## 工作台需求(唯一需求来源,没写的就是不做)
- 工作台名称:{{…}}
- 面板信息架构:{{2~5 个面板,逐个写:id / 标题 / 用途 / 参考哪个示例页}}
- 数据形态:{{核心实体、指标、维度;暂无真实数据源时按领域设计演示数据,确定性造数(service/seed.mjs)}}
- agent 工具:{{3~5 个,写明每个回答什么问题;描述注明数据范围与"演示数据"披露}}

## 阶段与完成标准
1. 数据层:service/api.mjs 查询函数(形状=页面所需)→ node 直测每个函数 → index.js 注册路由
2. 页面层:逐面板实现(范式照对应示例页)→ 每页带 .wb-page 根容器 + 四态 → 注册进 PANELS
3. 工具层:index.js 定义 wb_* 工具(可选参数省略 required)→ node 直测
4. 门禁:每次改动 npm run guard && npm run build 全绿(guard 含红线/边界/tsc/渲染冒烟)
5. 交付:npm pack 产出 tgz,装入全新 profile 启动成功;输出简短交付说明(访问地址、面板与工具清单、已知差异)

## 硬性约束(违反即返工)
- 不 fork dsh;页面组件零 dsh import,耦合只在 src/client.tsx 注册层
- 主代码不 import src/examples;不改 examples/ 与 theme.ts
- SVG 内不放文字(HTML 覆盖层);ctx.effect 必须可清理;图标先穷举官方图形名再决定是否自绘
- 不确定的 dsh API:先实测最小用例,不要猜

## 汇报要求
每阶段完成后汇报验证证据(命令输出/断言结果)再继续;卡住时先说明在哪一步、什么报错,不要静默换方案。
```

## 填写示例(门店运营工作台)

- 工作台名称:门店运营工作台
- 面板信息架构:① ops-home / 运营首页 / 今日关键指标与异常提醒(参考总览页) ② ops-stores / 门店列表 / 搜索与单店速览(参考列表页) ③ ops-tasks / 任务看板 / 任务分派与跟进(参考列表+表单页)
- 数据形态:实体=门店、任务、日销售汇总;指标=实收/订单/任务完成率;维度=区域/门店/日期
- agent 工具:① ops_store_daily 某店某天销售速览 ② ops_task_summary 任务完成汇总 ③ ops_store_lookup 门店模糊查找
